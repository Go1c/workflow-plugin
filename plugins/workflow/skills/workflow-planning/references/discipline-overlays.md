# 专业覆盖层

覆盖层不是第二套模板。每张可执行卡选择一个主覆盖层，再把真正适用的跨切面约束合并进基础模板；不要把多个可独立交付的主责角色拼成万能 Agent。

## 目录

- 来源与探索：`[原始需求]`、`[预研]`
- 设计与内容：`[策划·系统/玩法]`、`[策划·关卡/内容]`、`[叙事/本地化]`、`[UX/UI]`
- 资产生产：`[美术]`、`[技术美术]`、`[动画/VFX/音频]`
- 工程与运营：`[测试·用例]`、各类 `[程序]`、`[数据/运营/发布]`、`[集成]`
- 质量收口：`[Review]`、`[测试·收尾]`

## `[原始需求]` 来源记录

- **用途**：需求源真值与变更控制，不是等待某个 Agent“实现”的任务。
- **必须写入**：原始描述、来源与日期、附件/链接清单、决策账本、已确认假设、目标/范围/非目标、交付轨道、决策门、冲突处置和变更影响规则。
- **变更**：后续修改列出受影响的 Requirement、合同与验收，不静默改写下游决定。

## `[预研]` 覆盖层

- **身份**：负责降低一个明确交付风险的原型/研究负责人。
- **详细要求**：写明可证伪假设、当前未知、时间盒、最小实验、代表性数据/设备、观测指标、停止阈值和不进入生产的原型边界。
- **交付**：原始证据、可复现步骤、结论置信度、建议选项、决策人和对下游卡的明确解锁/取消结果；不得把“试出来再说”当验收。

## `[策划·系统/玩法]` 覆盖层

- **身份**：产品负责人、制作人或游戏系统/玩法策划。
- **详细要求**：玩家/用户与场景、价值、核心循环、状态机、输入反馈、规则优先级、失败/恢复、数值与可调参数、权限、反滥用、成功指标和阶段范围。
- **交付**：可版本化的规则/数值表、流程与状态说明、术语，以及设计、QA、程序和数据共同消费的锁定合同。

## `[策划·关卡/内容]` 覆盖层

- **身份**：关卡、任务或内容设计负责人。
- **详细要求**：节奏与难度曲线、入口/出口、触发和状态、内容 schema、复用模块、失败恢复、可玩性目标、内容预算和编辑器/管线约束。
- **交付**：白盒/关卡稿、内容表与验证路线；大型场景、关卡和二进制内容指定唯一写入者与集成方式。

## `[叙事/本地化]` 覆盖层

- **身份**：叙事或本地化负责人；只选择本卡实际需要的主责。
- **详细要求**：角色与世界观约束、文本 key、变量/复数/性别规则、字数与 UI 空间、语音/字幕同步、敏感内容、回退语言和伪本地化。
- **交付**：版本化脚本/字符串表、上下文注释、录音或翻译 Brief、导入格式和目标语言验收证据。

## `[UX/UI]` 覆盖层

- **身份**：UX 架构师或 UI 设计师；复杂交付按独立成果拆卡。
- **详细要求**：信息架构、逐屏流、路由、输入映射、焦点/手柄导航、loading/empty/error/disabled/no-permission 状态、文案、响应式/安全区、键盘和无障碍。
- **交付**：设计源、组件/页面状态表、交互和动效说明、设计 token 与偏离规则，足以让 QA 编写用例并让实现者客观还原。

## `[美术]` 覆盖层

- **身份**：游戏美术或视觉资产负责人。
- **详细要求**：风格支柱、资产与变体清单、构图/镜头、尺寸/格式/色彩空间、贴图/面数/LOD/内存预算、命名、源文件、导出规则、原创与授权边界。
- **交付**：可生产 Brief、源资产、导出资产、版本/来源记录，以及在目标引擎、平台和代表性场景中的评审证据。

## `[技术美术]` 覆盖层

- **身份**：技术美术或资产管线负责人。
- **详细要求**：shader/material、rig、导入器、生成工具、资产校验、批处理、LOD/压缩、渲染兼容和性能预算；明确 DCC 与引擎版本。
- **交付**：稳定管线、示例资产、自动校验、性能捕获、使用/回滚说明；共享导入配置和生成入口由本卡唯一拥有。

## `[动画/VFX/音频]` 覆盖层

- **身份**：动画、VFX 或音频中的单一主责；需要并行生产时分别拆卡。
- **详细要求**：触发时机、状态/混合、时长与同步、事件接口、循环/中断、空间化、可读性、强度/闪烁/响度、平台预算和降级策略中的适用部分。
- **交付**：源文件与运行时资产、事件/参数表、导入设置，以及目标镜头、设备和性能预算下的在引擎证据。

## `[测试·用例]` 覆盖层

- **身份**：QA 测试设计负责人。
- **详细要求**：在生产代码前把已锁需求转换成风险驱动用例，覆盖正常链、边界、失败恢复、并发/幂等、输入设备、存档/迁移、联网/重连、性能、兼容、视觉、无障碍、本地化、认证、集成、E2E 和回归中的适用部分。
- **交付**：可追溯用例矩阵、代表性 fixture/设备/环境、自动化层级映射、手工或在机证据要求、阻断条件和最终收尾清单。

## `[程序·协议/公共]` 覆盖层

- **身份**：技术负责人和共享合同维护者。
- **详细要求**：锁定 API/DTO、网络协议、存档/数据 schema、内容格式、公共接口、错误语义、鉴权、版本/兼容/迁移/回滚、遥测、性能预算与共享 fixture。
- **交付**：下游可直接消费的稳定合同、合同测试、迁移与集成说明；不夹带可独立拆出的具体业务功能。

## `[程序·服务端]` 覆盖层

- **身份**：服务端或在线系统工程师。
- **详细要求**：领域规则、存储与事务、并发/幂等、鉴权与隔离、作弊/滥用、错误、可观测性、迁移/回滚、容量和服务端测试。
- **验证**：对可自动化行为执行 Red-Green-Refactor，并验证失败恢复、兼容与代表性负载；不伪造不可运行的环境结果。

## `[程序·客户端]` 覆盖层

- **身份**：游戏客户端、前端或运行时工程师。
- **详细要求**：消费锁定协议与设计，覆盖状态/场景生命周期、输入与反馈、缓存/同步、离线/重连、存档、资源加载、目标平台、帧时/内存/包体预算、无障碍和客户端测试。
- **验证**：先把适用 QA 用例落实到最低可靠层级的失败测试，再实现；补充目标设备/引擎中的集成、性能或视觉证据。

## `[程序·工具/构建]` 覆盖层

- **身份**：编辑器工具、内容管线、构建或发布工程师。
- **详细要求**：输入输出格式、增量与缓存、确定性、错误可见性、CI、制品签名、平台矩阵、权限、回滚和对创作者工作流的兼容。
- **交付**：可重复工具/构建、自动校验、运行手册与失败恢复证据；生成文件、锁文件和发布入口设置唯一所有者。

## `[数据/运营/发布]` 覆盖层

- **身份**：数据分析、LiveOps、发行或发布中的单一主责；职责可独立时分别拆卡。
- **详细要求**：事件 schema 与口径、隐私/留存、实验分流、配置版本、时区、灰度、开关、监控告警、客服/运营手册、平台提交和回滚中的适用部分。
- **交付**：可验证的仪表/查询或发布计划、演练证据、Go/No-Go 条件和责任人；不得把生产发布默认为规划 Agent 已授权动作。

## `[集成]` 覆盖层

- **身份**：集成负责人和共享热点唯一所有者。
- **输入**：各专业交付包、锁定合同、基线、集成顺序和验证矩阵。
- **交付**：可回滚的集成候选、冲突处置记录、组合验证和完整变更边界；不借集成之名扩写各卡业务范围。

## `[Review]` 覆盖层

- **身份**：在可行时未参与实现的整体 reviewer。
- **输入**：全部相关 Requirement、合同、交付报告、共同基线到集成候选的完整代码/资产/配置 diff 与真实验证证据。
- **详细要求**：对需求满足度、正确性、安全、合同、数据边界、迁移/回滚、性能/资产预算、错误处理、测试有效性和知识同步做对抗审查。
- **交付**：放行或退回结论、带证据和所有者的分级 findings；不直接夹带未授权修复。纯非代码交付使用相应领域评审，不创建空的 Code Review。

## `[测试·收尾]` 覆盖层

- **身份**：最终 QA 或领域验收负责人。
- **前置**：适用的整体 Review/专业评审已放行，集成候选和环境可识别且可回滚。
- **详细要求**：执行前置矩阵，核对自动化、集成、E2E、在机/在引擎、视觉、性能、无障碍、本地化、失败恢复、认证与回归中的适用部分。
- **闭环**：问题退回真实所有者；修复后重新通过受影响 Review 与验证。全部通过才建议完成，不擅自流转或归档。
